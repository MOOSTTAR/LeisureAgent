\section{Planning 策略 —— ReAct + Plan\&Execute 混合模式}

LeisureAgent 由 18 个 LangGraph 节点按 ReAct（推理-行动-观察）与 Plan\&Execute（计划-执行）混合模式协作运行。LLM 调用失败时自动降级规则逻辑，确保核心流程不中断。

\subsection{工作流与路由}

{\footnotesize
\begin{verbatim}
  load_session → classify_intent ──[路由]──┐
    ├─ casual / out_of_domain → direct_reply → END
    ├─ inquiry → search_inquiry → present_inquiry → END
    ├─ new_plan → analyze_goal → search_candidates → detect_exceptions
    │    ⇢ critical_gap & retry<2 → adjust_search → search_candidates (loop)
    │    → compose_plan → persist_plan
    │    ⇢ auto_execute → execute_bookings → finalize_executed → END
    │    ⇢ manual → present_plan → END
    ├─ feedback → analyze_feedback → (search?) → compose → ... → END
    └─ confirm → execute_bookings
         ⇢ failure & retry<2 → replan_execute → persist → execute (loop)
         ⇢ ok → finalize_executed → END
\end{verbatim}
}

\textbf{意图分类}采用三层优先级：
\begin{enumerate}[label=(\arabic*)]
  \item \textbf{快速规则}：确认/反馈关键词 + pending 方案 → 直接路由；工作日关键词 → rejection。命中即返回，不调 LLM；
  \item \textbf{LLM 分类}：轻量模型（temperature=0, max\_tokens=512），一站式输出意图类型 + 直接回复文案；
  \item \textbf{TF-IDF 语义降级}：char n-gram + 余弦相似度，支持模糊匹配（如"哈喽"→CASUAL）。
\end{enumerate}

LLM 生成方案后经\textbf{四层保障}确保质量：① JSON 严格校验（提取→清洗→Pydantic 校验，最多 3 次重试）；② 多日校验（day\_num 分布不符 → LLM 重试 → 规则强制拆分）；③ 结构安全网（缺失 dining/play → 自动补齐）；④ LLM 降级（调用失败 → 规则编排兜底）。

\textbf{编排硬约束}：活动时序固定（游玩→缓冲→用餐）；用餐不重复（用户指定优先）；停留 5--360 min；多日每天至少 1 项。

\subsection{咨询模式与并发安全}

\textbf{咨询模式（inquiry）}：用户输入含领域关键词但非规划意图时，走轻量级浏览路径：\texttt{search\_inquiry\_node} 搜索 → \texttt{present\_inquiry\_node} 返回 InquiryEvent → 前端展示 Yes/No/Other 弹窗。

\textbf{并发安全}：SQLite 单连接 + \texttt{threading.Lock()} 写锁 + WAL 模式（并发读、串行写）。预约操作使用 \texttt{BEGIN IMMEDIATE} + \texttt{UPDATE WHERE current $<$ max} 原子 SQL，\texttt{rowcount=0} 判满，杜绝 TOCTOU 竞态。

\section{异常处理机制}

\begin{table}[ht!]
\centering\footnotesize\setlength{\tabcolsep}{3pt}
\begin{tabular}{p{2.2cm}p{3cm}p{7cm}}
\toprule
\textbf{机制} & \textbf{覆盖节点} & \textbf{处理策略} \\
\midrule
LLM 降级 & classify /\newline analyze /\newline compose &
LLM 调用失败 $\to$ 规则逻辑兜底：TF-IDF 语义匹配替代 LLM 分类（classify）、默认约束提取（analyze）、场景配置驱动编排（compose）。关键路径不依赖 LLM 可用性。 \\

ReAct\newline 搜索自愈 & detect →\newline adjust →\newline search &
关键类别无可用候选 $\to$ 放宽距离约束 50\% $\to$ 重新搜索。上限 2 次，耗尽后通过 gap\_report 告知用户缺口，不给出凑合方案。 \\

ReAct\newline 执行自愈 & execute→\newline replan→\newline persist→\newline execute &
预约失败 $\to$ 从原始 candidates 找同类替代（不调 LLM）$\to$ 重新持久化执行。上限 2 次。 \\

预约名额\newline 不足 & persist /\newline execute &
持久化时检测 \texttt{current $\ge$ max} → 返回"预约名额已满"；执行时原子 \texttt{UPDATE WHERE current $<$ max}，\texttt{rowcount=0} 判定满额，触发执行自愈。 \\

结构安全网 & compose &
LLM 产出缺少 dining（用餐）或 play（游玩）项 $\to$ 从候选池按场景优先级确定性补齐，每次触发记录 safety\_net 指标用于追踪 LLM 产出质量。 \\

输入安全 & load\_session &
22 个正则模式覆盖中英文：指令覆盖、角色劫持、提示词提取、SQL 注入标记。控制字符与零宽字符自动清洗。2000 字符上限。拦截后返回 guard\_reject 事件。 \\

结构化\newline 输出保护 & invoke\_\newline structured &
JSON 提取 → 语法清洗（单引号/尾部逗号/中文标点）→ Pydantic 校验 → 业务校验 → 错误回传 LLM 重试。最多 3 次，3 次均失败则抛异常触发上层降级。 \\

配置校验 & 启动时 &
\texttt{validate\_config()} 检查当前 provider 对应的 API key 及必需配置，缺失则立即 WARNING，不等到首次 LLM 调用才报错。 \\

可观测性 & 全局 &
JSON 结构化日志输出；LLM 调用追踪（节点名、耗时、成功/失败、token 用量）；安全网触发计数。数据持久化到 SQLite metrics\_counter 表，\texttt{GET /api/agent/metrics} 端点可查询。 \\
